# RafaDex — Remove Unused Cry Audio Pipeline — Design Spec

**Date:** 2026-08-09
**Status:** Approved design, pending implementation plan

## What

Removes the Pokémon "cry" (roar/shout) audio pipeline, the 1025 committed `.m4a`
files it produces, and every reference to them in the build, the runtime app, and
the tests. Cries have not played anywhere in the UI since the 05/08/2026 round
(the ⚡ button on the detail screen and the game-start roar were removed, along
with `Sound.cry()` in `audio.js`) — this round removes the now-dead generation
and shipping of the audio files themselves, deferred at the time as "a separate
round" if the app's footprint ever needed shrinking.

## Non-goals

- The source `.ogg` files in `~/project/pokedex/data/cries/` are untouched — that
  project is read-only from RafaDex's build and owns its own media independently.
- No change to sprite conversion, `dex.js` generation, fonts, colors, or any other
  pipeline output.
- No change to the pronunciation (🔊) or full-card narration (📖) features — both
  are `speechSynthesis`, unrelated to the recorded cry audio.

## The changes

**`build.py`**
- Remove `convertCry()`.
- `buildAssets()` stops reading `data/cries/{id}.ogg` from the pokedex project and
  stops writing `assets/cries/{id}.m4a`; the `jobs["cry"]` counter goes away.
- `renderPrecacheJs()` stops emitting the `assets/cries/{id}.m4a` entry per id.
- `main()`'s missing-outputs check drops the `.m4a` existence check.

**`app.js`**
- `genAssets(gen)` (used by the parent "download generation for offline use"
  control) stops including the cry URL — a generation download is now just the
  two sprite sizes per Pokémon.

**`assets/cries/`**
- `git rm` all 1025 `.m4a` files (~13MB) — nothing generates or references them
  anymore, so nothing regenerates the directory.

**`precache.js`**
- Regenerated by `build.py` as a side effect of the `build.py` changes above (Gen 1
  precache list, sprites only). No hand-editing.

**`sw.template.js` — runtime cache purge**
- The `activate` handler gains a step, alongside the existing shell-cache cleanup:
  open the `rafadex-runtime` cache, list its keys, delete any request whose URL
  matches `/assets/cries/`. This runs on every activation but is idempotent —
  after the first successful purge on a device there is nothing left to match.
  This is what clears the ~13MB of already-downloaded cries from a phone that
  installed the app before this change (e.g. Rafael's), without the user doing
  anything beyond letting the PWA update as usual.

**`tests/test_build.py`**
- `testConvertSpriteAndCryProduceFiles` → keep only the sprite half (drop the
  `convertCry`/`.ogg` half) and rename to `testConvertSpriteProducesFile`.
- `testBuildAssetsSkipsUpToDateOutputs` → drop the `.ogg` fixture and the
  `convertCry` monkeypatch; call count goes from 3 (thumb+full+cry) to 2.
- `testRenderPrecacheJsListsGen1AssetUrls` → drop the `.m4a` assertion; add an
  assertion that no `.m4a` URL appears in the output at all.

**`CLAUDE.md`**
- Drop `assets/cries/*` from the list of paths `python3 build.py` writes.

## Testing

- `pytest -q` covers the pipeline-side removal (build.py + tests above).
- `ruff check .` clean, per repo convention.
- The service-worker purge cannot be meaningfully unit-tested (no SW test harness
  in this repo); verify live: serve locally, install as a PWA (or open DevTools →
  Application), pre-seed the `rafadex-runtime` cache with a `.m4a` entry, trigger
  an update, and confirm the entry is gone from Cache Storage after `activate`.
- After deploy: on the real iPhone install, force an update and confirm via
  DevTools remote inspector (or just trust the purge logic + local verification,
  if remote inspection isn't practical) that cry entries are gone and the app
  still browses/plays sounds (pronunciation, narration, UI pop) normally.
