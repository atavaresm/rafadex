# RafaDex Visual Identity v2 — Design Spec

**Date:** 2026-08-01
**Status:** Approved design (via visual brainstorming companion — 3 rounds of mockups), pending implementation plan

## What

A second visual pass over the type-color system introduced in the v1 visual design
system (2026-07-22, see `2026-07-22-visual-design-system-design.md`). That round
replaced flat type colors with a diagonal light→base→dark gradient. Living with it day
to day, the app works well but two things still feel off: the muted "official" Pokémon
type colors (e.g. Fire `#f08030`, Water `#6890f0`) read as flat/dull even with the
gradient, and the typography doesn't feel playful enough for a 3–6-year-old. This round
moves the mood from "collectible card gradient" to **"vibrant toy/plastic"**: solid
saturated colors, a plastic-shine highlight, chunkier rounded shapes, a rounder display
font for names/labels, and a consistent icon set replacing the system emoji for types.

Brainstormed visually via the companion tool across 3 mockup rounds: overall mood (3
directions shown — TCG Holo, Cartoon Sticker, Toy Vibrant — Toy Vibrant won clearly,
confirmed twice against Cartoon Sticker before settling), the treatment applied across
Home + grid together (approved as shown — "tá ótimo assim, gostei do brilho"), and
type-icon style (outline pictogram beat solid pictogram and beat keeping the emoji).

## Non-goals

- **No change to Rafael-facing interaction**: routing, favorites, evolution strip,
  swipe, the game, and audio are all unaffected — this is a visual-only pass.
- **No change to the 18 type base hex values** in `build.py`'s `TYPES` dict /
  `window.TYPES` — the vivid colors and icon treatment are derived from those existing
  values at render time, not hand-authored per type.
- **No new screens, no data-shape changes.**
- **No literal card-frame border** (same rejection as v1's option "C").
- **Ghost and Dragon keep their current emoji** (👻 🐉) — no acceptable Material
  Symbols match was found for either; every other type switches to the new icon (see
  section 3).

## 1. Palette — flat vivid colors (replacing the v1 gradient)

Every place that currently renders a type's v1 gradient (`typeGradient()` in `app.js`)
instead renders one flat, saturated color derived from the same base hex:

**Formula:** convert the type's base hex to HSL, keep hue roughly unchanged, push
saturation and lightness toward a fixed "toy" target (bright, saturated, but not
neon/washed out), then convert back to hex — one deterministic helper computed at
render time from `window.TYPES[key].color`, same "single stored hex, computed
derivative" pattern v1 used for its gradient stops.

**Important caveat for the implementer:** the mockups' 5 sample colors (Fire
`#ff7a1a`, Water `#2f8dff`, Electric `#ffce00`, Grass `#4bc45e`, Steel `#9aa5c9`) were
hand-picked to show the *mood*, not generated by a single mechanical formula — a quick
HSL check shows they don't share one consistent saturation/lightness target (e.g.
Fire's and Electric's vivid versions sit near 100% saturation, but Grass's sits close
to its *original* ~52% saturation because mid-lightness greens already read as vivid
at lower saturation than oranges/blues do — pushing Grass to 100% saturation the same
way produces a neon lime, not the approved look). A single "saturation = 100%" rule
will not reproduce what was approved. Treat the 5 mockup colors as the target look to
match by eye per type, not as formula output to replicate exactly — derive a starting
formula, then live-verify and hand-tune per type against that reference (see Testing),
the same empirical way v1 arrived at its own gradient percentages.

**Applies to the same 3 surfaces v1 touched** (now flat instead of gradient):
- Home screen type buttons (`.type-btn`)
- Type-world grid cards (`.mon-card`)
- The shared `topbar(title, backHash, tint)` background mechanism (detail screen, the
  type-world screen, the game screen) — `document.body.style.background` becomes the
  flat vivid color instead of a gradient.

## 2. Plastic shine + chunky shape

Buttons and cards — things that read as discrete objects — get:
- A soft white radial highlight anchored to the top of the element, same shape/opacity
  formula for every type (the highlight itself is colorless, so it doesn't need a
  per-type calculation).
- A bigger corner radius than today (~24–26px on Home tiles, ~20px on grid cards) and
  a hard, non-blurred offset shadow beneath the element (e.g. `0 4px 0
  rgba(0,0,0,.15)`), for a stacked-plastic-piece look.
- A matching drop-shadow under the Pokémon sprite artwork itself, so it reads as
  sitting on the surface rather than pasted flat.

**Exception — the detail screen's full-bleed background:** flat vivid color only, **no
shine**. The shine reads as light reflecting off a discrete toy-like object; at
full-viewport background scale it looked wrong in review, so the background stays flat
while the shine is reserved for buttons, cards, and sprite shadows.

## 3. Type icons — outline pictograms replacing emoji

Material Symbols Rounded, **outline weight** (`FILL 0`), rendered in white, replacing
the system emoji everywhere a type icon currently appears:
- Home screen type button icons (currently 56px emoji)
- The small circular type badges near the detail screen's back button and in the grid
  card's corner (currently rendered by `typeBadgeHtml()`)

The small badges also drop v1's radial-gradient "bead" treatment and become **flat
vivid circles** matching the big tiles — full consistency, no gradient left anywhere
in the type-color system after this round.

**Icon mapping (16 of 18 types — Ghost and Dragon are the emoji exceptions):**

| Type | Icon (Material Symbols ligature) |
|---|---|
| Normal | `star` |
| Fire | `local_fire_department` |
| Water | `water_drop` |
| Electric | `bolt` |
| Grass | `grass` |
| Ice | `ac_unit` |
| Fighting | `sports_martial_arts` |
| Poison | `science` |
| Ground | `terrain` |

Exact ligature names to be verified against the live Material Symbols Rounded set
during implementation — a couple (Fighting and Rock are the least certain) may need a
substitute if the chosen name doesn't render or doesn't read clearly at small size.

## 4. Typography

Fredoka (weight 700) replaces Baloo 2, **scoped to exactly the surfaces that carry the
new vivid color**: Pokémon names (grid card, detail screen) and the Home button type
labels. Everything else — header, footer, screen titles (e.g. "Fogo"), the "Quem é
esse Pokémon?" banner, buttons, pills — stays in Baloo 2, unchanged. No size changes
beyond what v1 already established.

## 5. What stays exactly as it is

Pills (white/cream background, brand-red text, number/generation left + type badge(s)
and power right), the sound/evolution/dex round buttons, the evolution strip, the
parent-facing search and gear panels, favorites, the fixed header/footer, and all
audio/interaction logic.

## Implementation notes

- Replace the `shadeColor`/`typeGradient` call sites (`app.js:83` Home buttons,
  `app.js:140` grid cards, `app.js:69` `topbar` tint) with a new flat `vividColor(hex)`
  helper. `shadeColor` itself may still be needed elsewhere (verify before deleting).
- `typeBadgeHtml()` (`app.js:48`) changes twice: background becomes `vividColor(hex)`
  instead of `typeGradient(hex, "radial")`, and its emoji lookup is replaced by the new
  icon lookup (falling back to emoji for Ghost/Dragon).
- New Google Fonts additions: Fredoka (weight 700) and Material Symbols Rounded
  (variable font, `FILL` axis at 0) alongside the existing Baloo 2 `<link>`.
- `window.TYPES[key].emoji` stays in the data as-is (still needed for Ghost/Dragon and
  anywhere emoji remains relevant) — the icon mapping is a new, separate small lookup
  table, not a change to `build.py`'s data shape.
- Any new font/CSS asset added to `index.html` needs a service-worker version bump —
  this exact class of bug has bitten the last two visual rounds (see
  `feedback_pwa_precache_review` in memory / the diary entries for 2026-07-22).

## Testing

- Frontend-only visual change — no new `pytest` coverage needed.
- Live verification per house rule (local server, per `CLAUDE.md`): Home screen with
  all 18 tiles (new colors + new icons legible at a glance), a dual-type grid + detail
  check (Charizard: Fire + Flying icons both render correctly side by side), the two
  emoji-fallback types (Ghost, Dragon) don't look visually out of place sitting next to
  icon-based tiles, and an offline/precache check confirming the new font assets
  survive a killed server (the recurring bug class from `feedback_pwa_precache_review`).
- Saturation/lightness spot-check across **all 18 types**, not just the 5 demoed in
  mockups (Fire, Water, Electric, Grass, Steel) — especially types whose official color
  sits near the extremes (Fairy `#ee99ac` light, Dark `#705848` and Ghost `#705898`
  dark, Steel `#b8b8d0` already desaturated) to confirm the HSL clamp doesn't wash out
  or crush any of them.
