# Pokémon Maze Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a third game mode to RafaDex — an 8×8 maze the player solves by dragging a
finger from entrance to exit, painting the corridor, picking up three Gen 1 Pokémon hidden
in off-path dead ends.

**Architecture:** One new vanilla module `maze.js` (generator + screen), one new hash route
`#maze`, one new Home button. The maze is a DOM grid of 64 cells with CSS-border walls;
painting is cell-granular, driven by `pointerdown/move/up` on the grid container with
`document.elementFromPoint` for hit testing. No canvas, no library, no persisted state.

**Tech Stack:** Vanilla JS (ES2020, no modules/bundler), CSS, Node 26 for the generator
verification script only. Python `build.py` regenerates `sw.js`.

**Spec:** `docs/superpowers/specs/2026-09-05-pokemon-maze-game-design.md`

## Global Constraints

- Repo artifacts (code, comments, commits, docs) in **English**; all user-facing UI copy in
  **pt-BR**.
- Vanilla JS only: **no canvas, no new library, no bundler, no `fetch()` for data**. New
  modules load via `<script>` tags and talk to each other through globals, exactly like
  `capture.js` and `battle.js`.
- **No `localStorage` key is added by this feature.** The maze persists nothing.
- Collectible pool is **Generation 1 only (#1–151)** — the set guaranteed to be precached,
  so the mode works in airplane mode.
- Grid is **fixed 8×8**. No score, timer, lives, failure state, or progressive difficulty.
- Every new JS file MUST be added to **both** `index.html` (a `<script>` tag) and
  `SHELL_CORE` in `sw.template.js`, then `sw.js` regenerated by `python3 build.py`. A file
  missing from `SHELL_CORE` works online and vanishes in airplane mode.
- All URLs relative (GitHub Pages serves the app under `/rafadex/`).
- New animations get a `@media (prefers-reduced-motion: reduce)` escape hatch, matching the
  existing `.bounce` / `.grass-patch.shake` / `.throw-ball.miss` rules.
- Branch: `feat/pokemon-maze-game`, already created from `develop`. Conventional commits.

### Task 1: Maze generation and the Node verification script

Pure logic, no DOM. This is the one part that can fail silently — an unsolvable maze or a
maze with nowhere to hide collectibles ruins a round without raising an error — so it is
the one part that gets a real automated check.

**Files:**
- Create: `maze.js`
- Create: `tools/verify-maze.js`

**Interfaces:**
- Consumes: nothing. (`gen1Ids()` from `capture.js` is referenced only as a default
  argument evaluated at call time, so `maze.js` loads fine in Node where it does not exist.)
- Produces:
  - `MAZE_SIZE` — number, `8`.
  - `MAZE_COLLECTIBLES` — number, `3`.
  - `MAZE_DIRS` — `{N:[0,-1], S:[0,1], E:[1,0], W:[-1,0]}` (`[dx, dy]`).
  - `mazeGenerate(size = MAZE_SIZE, rand = Math.random)` → `Set<string>[][]` indexed
    `[y][x]`, each set holding the open directions of that cell.
  - `mazeSolve(open, size = MAZE_SIZE)` → `Array<[x, y]>` from `[0,0]` to
    `[size-1, size-1]` inclusive, or `null` if unreachable.
  - `mazePlaceCollectibles(open, size = MAZE_SIZE, rand = Math.random, pool = null)` →
    `Array<{x, y, id}>`, at most `MAZE_COLLECTIBLES` entries, each in an off-path dead end.
  - `MAZE_MAX_ATTEMPTS` — number, `20`.
  - `mazeNewRound(size = MAZE_SIZE, rand = Math.random, pool = null)` →
    `{open, items}`. **This is what the screen calls** — it rolls a maze and its
    collectibles together, retrying when a maze cannot hide the full set (see Step 3).

Create `tools/verify-maze.js`:

```js
"use strict";

// Verifies the maze generator over many seeds. Run: node tools/verify-maze.js
// Not part of any CI job — this is a developer check for the one piece of the
// maze game that can fail silently.

const { mazeGenerate, mazeSolve, mazeNewRound, MAZE_SIZE, MAZE_COLLECTIBLES,
  MAZE_DIRS } = require("../maze.js");

const ROUNDS = 1000;
const POOL = Array.from({ length: 151 }, (_, i) => i + 1);

function fail(round, message) {
  console.error(`FAIL (round ${round}): ${message}`);
  process.exit(1);
}

function reachableCount(open) {
  const seen = new Set(["0,0"]);
  const queue = [[0, 0]];
  while (queue.length) {
    const [x, y] = queue.shift();
    for (const d of open[y][x]) {
      const [dx, dy] = MAZE_DIRS[d];
      const key = `${x + dx},${y + dy}`;
      if (!seen.has(key)) { seen.add(key); queue.push([x + dx, y + dy]); }
    }
  }
  return seen.size;
}

for (let round = 0; round < ROUNDS; round++) {
  const open = mazeGenerate();

  if (reachableCount(open) !== MAZE_SIZE * MAZE_SIZE) {
    fail(round, "maze is not fully connected");
  }

  for (let y = 0; y < MAZE_SIZE; y++) {
    for (let x = 0; x < MAZE_SIZE; x++) {
      for (const d of open[y][x]) {
        const [dx, dy] = MAZE_DIRS[d];
        const nx = x + dx, ny = y + dy;
        if (nx < 0 || nx >= MAZE_SIZE || ny < 0 || ny >= MAZE_SIZE) {
          fail(round, `cell ${x},${y} opens off the grid to the ${d}`);
        }
        const back = { N: "S", S: "N", E: "W", W: "E" }[d];
        if (!open[ny][nx].has(back)) {
          fail(round, `wall between ${x},${y} and ${nx},${ny} is not symmetric`);
        }
      }
    }
  }

  const path = mazeSolve(open);
  if (!path) fail(round, "entrance to exit is unsolvable");
  if (path[0][0] !== 0 || path[0][1] !== 0) fail(round, "solution does not start at 0,0");
  const last = path[path.length - 1];
  if (last[0] !== MAZE_SIZE - 1 || last[1] !== MAZE_SIZE - 1) {
    fail(round, "solution does not end at the exit");
  }

  // The screen always goes through mazeNewRound, so that is what gets the
  // full-set guarantee. Roughly 1 raw maze in 1100 can only hide two
  // collectibles; mazeNewRound is what makes that invisible to the player.
  const roundData = mazeNewRound(MAZE_SIZE, Math.random, POOL);
  if (roundData.items.length !== MAZE_COLLECTIBLES) {
    fail(round, `placed ${roundData.items.length} collectibles, expected ${MAZE_COLLECTIBLES}`);
  }
  const roundPath = mazeSolve(roundData.open);
  const onPath = new Set(roundPath.map(([x, y]) => `${x},${y}`));
  for (const item of roundData.items) {
    if (onPath.has(`${item.x},${item.y}`)) fail(round, "collectible sits on the solution path");
    if (roundData.open[item.y][item.x].size !== 1) fail(round, "collectible is not in a dead end");
    if (!POOL.includes(item.id)) fail(round, `collectible id ${item.id} is outside Gen 1`);
  }
}

console.log(`OK — ${ROUNDS} mazes: connected, solvable, symmetric walls, ` +
  `${MAZE_COLLECTIBLES} off-path dead-end collectibles per round.`);
```

- [ ] **Step 3: Write `maze.js` with the generator, solver, and placement**

Create `maze.js` at the repo root:

```js
"use strict";

const MAZE_SIZE = 8;
const MAZE_COLLECTIBLES = 3;
const MAZE_DIRS = { N: [0, -1], S: [0, 1], E: [1, 0], W: [-1, 0] };
const MAZE_OPP = { N: "S", S: "N", E: "W", W: "E" };

// Recursive-backtracker generation. Produces a perfect maze: fully connected,
// exactly one path between any two cells, guaranteed to contain dead ends.
function mazeGenerate(size = MAZE_SIZE, rand = Math.random) {
  const open = [];
  for (let y = 0; y < size; y++) {
    const row = [];
    for (let x = 0; x < size; x++) row.push(new Set());
    open.push(row);
  }
  const seen = open.map(row => row.map(() => false));
  const stack = [[0, 0]];
  seen[0][0] = true;
  while (stack.length) {
    const [x, y] = stack[stack.length - 1];
    const candidates = [];
    for (const dir of Object.keys(MAZE_DIRS)) {
      const [dx, dy] = MAZE_DIRS[dir];
      const nx = x + dx, ny = y + dy;
      if (nx >= 0 && nx < size && ny >= 0 && ny < size && !seen[ny][nx]) {
        candidates.push([dir, nx, ny]);
      }
    }
    if (!candidates.length) { stack.pop(); continue; }
    const [dir, nx, ny] = candidates[Math.floor(rand() * candidates.length)];
    open[y][x].add(dir);
    open[ny][nx].add(MAZE_OPP[dir]);
    seen[ny][nx] = true;
    stack.push([nx, ny]);
  }
  return open;
}

// Breadth-first search from the entrance to the exit. Returns the cells of the
// solution path in order, or null when the exit cannot be reached.
function mazeSolve(open, size = MAZE_SIZE) {
  const prev = { "0,0": null };
  const queue = [[0, 0]];
  while (queue.length) {
    const [x, y] = queue.shift();
    if (x === size - 1 && y === size - 1) break;
    for (const dir of open[y][x]) {
      const [dx, dy] = MAZE_DIRS[dir];
      const key = `${x + dx},${y + dy}`;
      if (!(key in prev)) { prev[key] = [x, y]; queue.push([x + dx, y + dy]); }
    }
  }
  if (!(`${size - 1},${size - 1}` in prev)) return null;
  const path = [];
  let cell = [size - 1, size - 1];
  while (cell) { path.push(cell); cell = prev[`${cell[0]},${cell[1]}`]; }
  return path.reverse();
}

// Hides collectibles in dead ends that are NOT on the solution path, so that
// exploring a wrong turn is where the reward is. Falls back to fewer items when
// a maze somehow offers fewer spots; the round stays playable and winnable.
function mazePlaceCollectibles(open, size = MAZE_SIZE, rand = Math.random, pool = null) {
  const path = mazeSolve(open, size);
  const onPath = new Set((path || []).map(([x, y]) => `${x},${y}`));
  const spots = [];
  for (let y = 0; y < size; y++) {
    for (let x = 0; x < size; x++) {
      if (open[y][x].size === 1 && !onPath.has(`${x},${y}`)) spots.push([x, y]);
    }
  }
  for (let i = spots.length - 1; i > 0; i--) {
    const j = Math.floor(rand() * (i + 1));
    [spots[i], spots[j]] = [spots[j], spots[i]];
  }
  const ids = pool || gen1Ids();
  return spots.slice(0, MAZE_COLLECTIBLES).map(([x, y]) =>
    ({ x, y, id: ids[Math.floor(rand() * ids.length)] }));
}

// Measured over 20,000 mazes: about 1 in 1100 offers only two dead ends that are
// off the solution path, which would silently short the round one collectible.
// Rather than degrade the round, roll again — each attempt succeeds ~99.9% of the
// time, so this effectively never loops twice, and the bound keeps it honest.
const MAZE_MAX_ATTEMPTS = 20;

function mazeNewRound(size = MAZE_SIZE, rand = Math.random, pool = null) {
  let best = null;
  for (let attempt = 0; attempt < MAZE_MAX_ATTEMPTS; attempt++) {
    const open = mazeGenerate(size, rand);
    const items = mazePlaceCollectibles(open, size, rand, pool);
    if (items.length === MAZE_COLLECTIBLES) return { open, items };
    if (!best || items.length > best.items.length) best = { open, items };
  }
  return best;
}

if (typeof module !== "undefined" && module.exports) {
  module.exports = { MAZE_SIZE, MAZE_COLLECTIBLES, MAZE_MAX_ATTEMPTS, MAZE_DIRS, MAZE_OPP,
    mazeGenerate, mazeSolve, mazePlaceCollectibles, mazeNewRound };
}
```

### Task 3: Painting the path with a finger

The core interaction: the three rules from the spec. Walls block the paint, dragging
backwards erases, everything else does nothing.

**Files:**
- Modify: `maze.js` — inside `renderMaze()`
- Modify: `style.css` — the trail class

**Interfaces:**
- Consumes: `MAZE_SIZE`, `MAZE_DIRS` (Task 1); the `cells` array and `open` grid from
  Task 2's `renderMaze()`.
- Produces (all local to `renderMaze()`, used by Tasks 4–6):
  - `path` — `Array<[x, y]>`, the painted cells in order; `let`, reassigned by the eraser.
  - `won` — boolean, `true` once the exit is painted.
  - `cellAt(x, y)` → the cell element.
  - `paintTo(x, y)` → void, applies the three rules against the head of `path`.
  - `onPaint(x, y)` → void, a hook called after a cell is newly painted. Task 2 leaves it
    empty; Task 5 fills in collection, Task 6 fills in the win check.

- [ ] **Step 1: Add the state and painting rules inside `renderMaze()`**

Insert after `cells[MAZE_SIZE * MAZE_SIZE - 1].classList.add("maze-goal");` and before
`stage.append(grid);`:

```js
  let path = [];
  let dragging = false;
  let won = false;

  function cellAt(x, y) { return cells[y * MAZE_SIZE + x]; }
  function head() { return path[path.length - 1]; }

  // Extension point: Task 5 collects a Pokémon here, Task 6 checks the win.
  function onPaint(x, y) {}

  function paintTo(x, y) {
    if (won) return;
    if (!path.length) {
      if (x === 0 && y === 0) {
        path.push([0, 0]);
        cellAt(0, 0).classList.add("trail");
        onPaint(0, 0);
      }
      return;
    }
    const [hx, hy] = head();
    if (x === hx && y === hy) return;

    // Rule 2: dragging back onto the previous cell erases the head.
    if (path.length >= 2) {
      const [px, py] = path[path.length - 2];
      if (x === px && y === py) {
        cellAt(hx, hy).classList.remove("trail");
        path.pop();
        return;
      }
    }

    // Rule 1: adjacent with no wall between -> paint.
    const dir = Object.keys(MAZE_DIRS).find(d =>
      MAZE_DIRS[d][0] === x - hx && MAZE_DIRS[d][1] === y - hy);
    // Rule 3: anything else (a wall, a skipped cell, off the grid) does nothing.
    if (!dir || !open[hy][hx].has(dir)) return;

    path.push([x, y]);
    cellAt(x, y).classList.add("trail");
    onPaint(x, y);
  }
```

- [ ] **Step 2: Wire the pointer events**

Insert immediately after the `paintTo` function, still inside `renderMaze()`:

```js
  function cellUnder(event) {
    return document.elementFromPoint(event.clientX, event.clientY)?.closest(".maze-cell");
  }

  grid.addEventListener("pointerdown", event => {
    const cell = cellUnder(event);
    if (!cell) return;
    const x = Number(cell.dataset.x), y = Number(cell.dataset.y);
    // A drag may only begin at the entrance (nothing painted yet) or at the head
    // of the existing path (resuming after lifting the finger). Anywhere else is
    // ignored: it must not start, move, or clear anything.
    const startable = path.length
      ? (x === head()[0] && y === head()[1])
      : (x === 0 && y === 0);
    if (!startable) return;
    dragging = true;
    grid.setPointerCapture(event.pointerId);
    paintTo(x, y);
  });

  grid.addEventListener("pointermove", event => {
    if (!dragging) return;
    const cell = cellUnder(event);
    if (!cell) return;
    paintTo(Number(cell.dataset.x), Number(cell.dataset.y));
  });

  const endDrag = () => { dragging = false; };
  grid.addEventListener("pointerup", endDrag);
  grid.addEventListener("pointercancel", endDrag);
```

## Self-Review (done at writing time)

**Spec coverage.** Every spec section maps to a task: entry button and `#maze` route
(Task 2), the three painting rules and drag-resume (Task 3), eraser-as-clear-all and
always-on next (Task 4), collectibles in off-path dead ends with the pip counter and Gen 1
pool (Tasks 1 and 5), the win celebration and pulsing next (Task 6), `SHELL_CORE` and
`touch-action: none` (Task 2), the generator verification script (Task 1), and the manual
device pass (Task 7). The spec's "no persisted state" constraint is satisfied by omission —
no task adds a `localStorage` key.

**One spec silence resolved here.** The spec says the eraser after a win keeps the maze and
the collected count, but not whether the maze can then be won again. Task 4 decides it
can: erasing sets `won = false` and drops the pulse, so the same maze replays. This is the
non-punishing reading, consistent with every other mode.

**One spec requirement satisfied for free.** The spec asks for the previous utterance to be
cancelled before speaking the next collectible's name. `Sound.speak()` already calls
`stopSpeech()` internally (`audio.js:36`), so Task 5 explicitly instructs *not* to add a
redundant call.

**A real bug caught before implementation.** Task 1's code was extracted from this plan and
run for real while writing it. The first run failed on round 41: about 1 raw 8×8 maze in
1100 (18 in 20,000 measured) has only two dead ends off the solution path, so it cannot
hide the full set of three collectibles. Rather than loosen the assertion or let the round
silently short a Pokémon, Task 1 gained `mazeNewRound()`, which rolls again — bounded at
`MAZE_MAX_ATTEMPTS = 20`, with the best attempt as a fallback that in practice never
fires. Re-verified after the fix: 50,000 rounds with zero short, and six consecutive
1,000-maze verification runs all green.

**Type consistency.** `mazeGenerate` / `mazeSolve` / `mazePlaceCollectibles` keep the same
signatures across Tasks 1, 2 and 5. The `open[y][x]` indexing order (row first) is used
consistently. `cells` is indexed `y * MAZE_SIZE + x` in Tasks 2, 3 and 5. `onPaint` is
declared in Task 3 and rewritten whole in Tasks 5 and 6 rather than patched blindly, which
is why Task 6 restates the entire function.
